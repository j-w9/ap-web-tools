# Audit: Hardware Report

Upstream: `upstream/HardwareReport/HardwareReport.js` and `index.html`, with the libraries it loads
(`Libraries/DecodeDevID.js`, `Array_Math.js`, `Param_Helpers.js`, `LogHelpers.js`) and
JsDataflashParser (see [`dataflash.md`](dataflash.md) and [`ardupilot.md`](ardupilot.md)).
Port: `apps/hardware-report/src/` (`analysis/` pure logic, `ui/` React).

The oracle harness `src/test-utils/upstream.ts` (added in this audit) runs the whole upstream page
in `node:vm` against a small recording DOM: upstream's `reset()` + `load_log()` /
`load_param_file()` run verbatim, and tests compare section text, plot data and layouts, `saveAs`
downloads and `alert` texts with the port's results. Status `convenience` marks a UI addition that
changes no computed result.

what upstream renders; compares the sensor-offset plot markers and axis range), `src/analysis/oracle-faults.test.ts`
(WDOG and InternalError section text), `src/analysis/oracle-params.test.ts` (parsed `params` and

tooltip for both bases, and the bytes and file names of the all/changed/minimal downloads for
several group selections) and `src/ui/oracle-release.test.ts` (`check_release` with a stubbed Octokit
against `ReleaseChecker` with the same GitHub answers). Inputs: both fixture logs, synthetic logs and
parameter files built to drive each branch fixed below.

### Remaining intentional differences

- Section layout: upstream fieldsets with ✅/❌ lines are tables with Yes/No and Healthy/Unhealthy
  badges; the same values are shown. The decode line for `decode_watchdog.py`, which upstream only
  logs to the console, is shown in a collapsed block.
- The release check uses `fetch` against the GitHub REST API instead of Octokit from a CDN, so the
  "offline" message (CDN import failed) becomes "failed to get whitelist". Concurrent checks may each
  request the tag list until one succeeds; results are unchanged.
- Crashes become errors: a boot message naming an unconfigured GPS (upstream throws in `load_gps`
  and leaves a half-built page) stops the report with an error naming the message; saving a parameter
  set containing NaN (upstream throws in `param_to_string`) shows the error. Missing health or WDOG
  fields, which make upstream throw, leave the value out instead.

### Remaining intentional differences

- Mission incomplete: the in-page message replaces `alert()` with the same text; the download still
  happens. A badge also marks incomplete sets before clicking (convenience; same computation).
- Empty sections are omitted rather than hidden; plot colours, trace display names (e.g. no `<br>`
  in power flag names) and layout differ (presentation).
- Board names come from the compiled table rather than a fetch of `board_types.txt`; the data is
  proven identical by test.
- The release check is a UI concern (part A's audit covers its logic).

## UI audit

Checked with `scripts/ui-audit.mjs` at 1440, 1024 and 390 px in both themes, in five states: empty,
`copter-files.bin` (real H743 board: files, data rates, performance), `copter-sitl.bin` (compasses,
two barometers, parameter changes, clock drift), the new `test-fixtures/ui-faults.bin` (watchdog,
internal errors, IOMCU, DroneCAN nodes, GPS boot messages, missions, fences and rally points) and
`test-fixtures/ui-params.param` (airspeed sensors and sensor positions). Both fixtures are built by
`src/ui-fixture.test.ts`. The audit configuration answers the GitHub release check from canned data
(Copter-4.6.3 is a tag, any other hash heads master), because GitHub rate-limits unauthenticated
requests long before a full run is done. Every section was read from the captures. The harness
reports no findings.

Changed (presentation only):

- Report tables are left-aligned, with numbers and actions right-aligned per column (`Table`'s
  `right`); device names no longer sat under right-aligned headings.
- Field and value tables (watchdog, IOMCU, parameter change history) size to their content instead
  of spreading two columns across the card.
- The DroneCAN release column wraps, so the release check text and the UID column are visible
  without scrolling sideways.
- Minimal configuration groups are a two-column grid, labels aligned beside their chips (one
  column on phones).
- Phone width: legends above the plots (`ui/Chart.tsx`).

Remaining known issues:

- "Primary: NaN" when `BARO_PRIMARY` or `ARSPD_PRIMARY` is missing is upstream's text (kept).
- Sensor tables scroll sideways on phones; their columns are all needed.
- In light mode, unticked and unavailable minimal configuration chips look alike (shell chip style).
