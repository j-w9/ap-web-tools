# Geofence Generator audit

Port: `apps/geofence-generator`. Upstream: `upstream/GeofenceGenerator/` (`index.html`,
`GeofenceGenerator.js`, `Readme.md`) plus `Libraries/Array_Math.js`, and the CDN libraries the
page loads: Leaflet 1.9.4, Leaflet.Editable 1.2.0, `@bagage/leaflet.restoreview` 1.0.1,
`@turf/turf@6` (6.5.0), leaflet-control-geocoder (unversioned, currently 3.x) and osmtogeojson
3.0.0-beta.5.

Oracle: `src/test-utils/upstream.ts` loads upstream `GeofenceGenerator.js` and `Array_Math.js` in
`node:vm` with stand-ins for the DOM, Leaflet, FileSaver and `fetch`, and the real Turf 6.5.0
`intersect` and osmtogeojson 3.0.0-beta.5. It drives `request()`, the popups and their Download
buttons, `add_crop`, `apply_crop` (vertex drag) and `generate_fence`. The tests compare the
request body, the parsed features, the map polygons, the popup text, the crop rectangle, cropped
features and the downloaded files (text and name) exactly, including repeated downloads.

Statuses: **identical** (same result, possibly restructured code), **presentation**,
**convenience** (changes no computed result), **browser-forced**, **reverted-in-this-audit**.

## Remaining intentional differences

- **Fence panel instead of a popup** (presentation): clicking a water body selects it; the panel
  shows the popup's name, point count and Download button.
- **Fence preview** (convenience): the panel and the map show the fence the next download will
  write, computed on a copy of the rings (`previewFence`), so it changes nothing; a test checks it
  equals the next download, including after earlier downloads have rotated the rings. It also shows
  the OpenStreetMap id and link, the fence's item list and the file text. After a download a note
  says the next file will differ (upstream's rotation).
- **Water bodies table** (convenience): lists the polygons on the map with the same name and point
  count as their popups, and selects them.
- **Search notice** (convenience): an HTTP error status or an Overpass `<remark>` is shown as a
  note. The features are still whatever upstream would load from that response.
- **Crop errors** (crash clause): where upstream's `apply_crop` throws, the port keeps the same
  partial set of polygons and shows the error.
- **Place search** (convenience): upstream's plugin auto-selects a single result, rate-limits to
  one request a second and caches results; the port lists every result for a click, and sends a
  request per submit. The request and the resulting map bounds are the same.
- **Rail facts** (presentation): the simplification limits and the searched tags (from the
  upstream Readme) are listed.
- **Dependencies**: `@turf/intersect` 6.5.0 with `polygon-clipping` 0.15.3 (what `@turf/turf@6`
  bundled when 6.5.0 was released) and `leaflet-editable` 1.2.0 are pinned to upstream's versions.

## UI audit

Checked with `scripts/ui-audit.mjs` at 1440, 1024 and 390 px in dark and light: the empty map, a
place search, the water bodies found, a selected fence with the file shown, and a crop. The
Overpass and Nominatim answers are recorded for Virginia Water (Surrey) in
`apps/geofence-generator/test-fixtures/` and served with `page.route`, so captures do not depend
on those services; tiles are live. The OSM attribution stays visible and legible in both themes
and the zoom control does not overlap it. Keyboard: place results are buttons, the table rows
have Select buttons, and the Leaflet map is focusable with its own keyboard panning. No console
errors, overflow or clipped text in any capture.

Changed (presentation only):

- The rail holds only controls (find a place, search, crop). The simplification limits and the
  OSM tags searched moved to a "How fences are made" section after the results, so on phones the
  map is no longer below a long reference list.
- Map height is 60 vh (at least 320 px) on phones, leaving page above and below to scroll by.
- Inline styles in the tables and the file toggle moved to classes in `ui/map.css`.

Remaining: on phones the water-body and fence tables scroll sideways inside their frame (the
shell's table pattern). Upstream's "Please Zoom in" text is kept as upstream wrote it.
