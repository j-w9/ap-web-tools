# PID Review audit

Port: `apps/pid-review`. Upstream: `upstream/PIDReview/` (`index.html`, `PIDReview.js`) plus
`Libraries/Array_Math.js`, `Libraries/fft.js`, `Libraries/LogHelpers.js` (`get_version_and_board`),
`Libraries/OpenIn.js` and the JsDataflashParser module they load.

Oracle: `src/test-utils/upstream.ts` runs the upstream `PIDReview.js`, `Array_Math.js`, `fft.js` and
`LogHelpers.js` in `node:vm` with the real upstream DataFlash parser and a small fake DOM (radio groups
behave as radios). `src/test-utils/synthetic.ts` writes logs with VER/MSG, parameter changes, data
gaps, timing jitter, decimated or time-limited messages, quiet spans and low logging rates.
`src/analysis/pipeline.test.ts` loads each log in both and compares, exactly: every controller found,
the overall time span, parameter sets, every batch (time, sample rate, every signal, computed output),
the batch FFT (bins, average rate, window correction, per-set window times and every complex
spectrum), and after each upstream handler (`re_calc`, `redraw`, `setup_axis`, `clear_calculation`)
the time-domain traces and x range, every spectrum trace (data, visibility, name), the step plot
(individual and mean traces) and the spectrogram (x, y, z, x range). Scenarios cover the two SITL
fixtures, copter with and without D FF, RATE controllers, plane (incl. quadplane `PIQ*`), rover,
amplitude/frequency scales, window sizes 64 to 1024, edited, empty, reversed and fractional time
inputs, the stale step mean, the low-rate noise estimate, vehicle detection, the window size alert and
the controller-switch selection rules. Mutating any of the reverted behaviours below makes the oracle
fail.

Statuses: **identical** (same result, possibly restructured code), **code-improved**,
**presentation**, **convenience** (changes no computed result), **browser-forced**,
**reverted-in-this-audit** (the port differed; now matches upstream).

## Remaining intentional differences

- **Invalid window size on load.** Upstream's `calculate()` throws inside `load()`, so the controller
  is never set up (no Tests table, no time-domain plots) and a later Calculate throws. The port shows
  the alert text, sets the controller up without spectra, and Calculate works once the size is valid
  (crash handling).
- **Plots after the window size changes.** Upstream leaves the previous FFT, step and spectrogram
  drawings on screen (not re-scaled) until the next calculation or controller change; the port shows
  them empty until Calculate. The numbers it shows after Calculate are the same.
- **Step plot visibility.** Upstream's `redraw_step` shows every mean again on each redraw regardless
  of the Tests boxes; the port keeps the step plot in step with the boxes (individual estimates when
  exactly one shown set has a mean, as `update_hidden` does). Trace data are identical.
- **Spectrum signal choices across controllers.** Effective selections are filtered to the signals the
  current controller has, as upstream; disabled ones are dropped on a controller change as upstream.
- Layout, wording, chips instead of checkboxes, unavailable controllers hidden instead of disabled,
  the log facts (file, vehicle, firmware, duration), the output y-axis title: presentation.
