# Telemetry Dashboard audit

Port: `apps/telemetry-dashboard`. Upstream: `upstream/TelemetryDashboard/` (`index.html`,
`TelemetryDashboard.js`, `WidgetEdit.js`, `Widgets/*`, `SandBoxWidgets/*.json`, `Examples/*.json`,
`Default_Layout.json`) plus `modules/MAVLink/mavlink.js` (with `runtime-fixes.patch`), Gridstack
10.3.1, Formio (`formio.full.min.js`), Monaco, tippy.js 6.3.7, Bootstrap 4.6.0 and Font Awesome 6.6.0
that it loads.

Oracles (`src/test-support/upstream-mavlink.ts` runs upstream `mavlink.js` in `node:vm`):

- `mavlink/legacy-message.test.ts`: random frames of every message both dialects define (more than
  250), decoded by upstream's `MAVLink20Processor.parseChar` and by the port's parser plus adapter,
  must be structurally identical (all fields, metadata, `_header`, `_msgbuf`, `_payload`, `crc`),
  including signed frames and every field the bundled widgets read.
- `mavlink/legacy-namespace.test.ts`: the rebuilt `mavlink20` global against upstream's constants,
  `map` entries and message classes.
- `connection/connection.test.ts`: heartbeat frames (plain and signed) byte for byte against
  upstream's `heartbeat.pack()`.
- `layout/link.test.ts`: link compression against upstream's `compress_layout` run as written.
- `layout/layout.test.ts`: bundled layouts and widgets are upstream's files (content unchanged).

Statuses: **identical** (same behaviour, restructured code), **presentation**, **convenience**,
**browser-forced**, **dialect** (follows from using `@apwt/mavlink`'s definitions).

## Differences

Presentation and browser-forced only:

1. **Page frame and styling.** CustomBuild look (`ToolPage`, dark chrome, yellow accent). The grid
   sits in a card that is one viewport tall instead of filling the window. Popups, the editor
   overlay and dialogs use the shared tokens; Formio forms keep a white background. Widget contents
   (user colours, white dashboard background) are unchanged.
2. **Icons.** Font Awesome 6 icon classes instead of the inline copies of the same Font Awesome SVGs;
   the connect icon's colour is set on the icon instead of its SVG path.
3. **Libraries from npm.** Gridstack 10.3.1, tippy.js 6.3.7, Bootstrap 4.6.0, Font Awesome 6.6.0 at
   upstream's versions; Formio 4.21.7 and Monaco 0.57.0 pinned (upstream loaded "latest" from unpkg).
   Monaco loads when the page starts but in the background; the editor opens once it is ready, as
   upstream's `load_editor` did. Bootstrap is in a CSS cascade layer so it does not restyle the shared
   chrome. Formio's stylesheet is injected as text because the build's CSS minifier rejects its IE
   hacks (browser/build constraint).
4. **Sandbox page as a build entry.** `sandbox.html` is a second Vite page of this app (it needs the
   bundled `mavlink20` global). `vite.config.ts` only builds `apps/*/index.html`, so it must list
   `apps/telemetry-dashboard/sandbox.html` as an extra input (dev serves it already).
5. **`alert()`/`confirm()`** are in-page dialogs with the same text and buttons.
6. **Palette position.** Opens at the click point (`followCursor` plugin), see above.
7. **Widget name as text** in the widget popup (upstream `innerHTML`), so a layout cannot inject HTML
   into the dashboard page.
8. **Crash clauses.** A malformed `#ws=` address shows the browser's error instead of stopping the
   page; leaving a page without a menu no longer throws.

Dialect (from using the shared, newer MAVLink definitions): messages added since upstream's
`mavlink.js` snapshot reach the widgets, and the "MAVLink message" select lists them; enum constants
follow the current definitions.
